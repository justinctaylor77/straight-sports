## Defects found during QA and what was done (honest log)

**Product defects (real bugs, fixed before the final run):**
1. *Tab/data mismatch on Rankings pages* (reported by Justin): the NFL bracket highlighted the CFB chip. Fixed with `shownSport()` (see "What's in this release"); regression unit test and TM-01…07.
2. *Restore screen crashed* (found by the first full QA, SY-07/08/09/13/15): the restore box was marked `data-part="restore"`, and `refreshParts()` empties every `data-part` element, so the form's buttons never existed and the binding dereferenced null. Fixed: the box is a plain element bound once.
3. *Account card on a server with no database/pepper* showed a Create button that could not work. It now says "Sync not available" (and no Create / "I already have a code" links); the card is shown whenever the server answers.
4. *Stale values overwrote another device's change* (found by SY-09): on a two-device conflict the device that synced second kept **all** of its own single values, so a device that only toggled "Straight news only" also reverted a theme change made on the other device. The client now remembers what it last synced and, on a conflict, keeps a single value only if this device changed it; lists are still unioned. Unit tests updated and extended.

**Test-script defects (the product was right, my test was wrong):** first full run 183/195 with 12 failures. SY-02 and SY-03 had wrong expectations (health endpoint, case-sensitive text); TM cases waited for a visible element that is only attached; U-17 (the secret scan) tripped on key-like test literals (pepper strings), which were rebuilt so test data does not look like a secret; SY-07/08 did not re-open the restore page after skipping onboarding (skipping onboarding always lands on Home, by design) and now wait for the network to settle; SY-15 now accepts the one browser network error that the deliberate offline step in SY-10 produces. GC-L-nhl failed on a transient ESPN 502: the harness retries 5xx twice and, if ESPN is still down, records a documented **SKIP** with the reason (it never counts as a pass).

SY-09 and SY-10 had the direction of the "Straight news only" toggle backwards (the app default is on, so the test's "other device" value was wrong); they now assert the correct values (theme=dark from device B, straightOnly=false from device A) and pass.

**Final full run: {{PASS}} pass / 1 fail / {{SKIP}} skip of {{TOTAL}}; the one failure is a flaky timeout, not a product defect.** BP-T-epl (Big plays UI, EPL tab) failed once with `waitForSelector('.bpo'): Timeout 20000ms exceeded` while the Premier League game feed was slow. Run alone (`QA_ONLY='^(BP-T)'`) all 5 BP-T cases passed (5/5), and the case passed again in the later subset runs. I raised that wait to 45 s (a test-only change). After the change I did **not** rerun the whole suite (about 25 minutes); instead I reran only the affected groups: BP-T, TM and SY (27/27 pass) and BP-FR/F/B/C/RM (11/11 pass), each with the test schema removed afterwards (`remaining=0`).
