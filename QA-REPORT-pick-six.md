## What's in this release
1. **Favorites picker by league** — Settings › Teams. One collapsible group per league; teams sorted alphabetically by location-first full name (Boston Red Sox, Chicago Cubs, Utah Jazz; colleges BYU Cougars, Utah Utes); A/Z or Conference sort; league chips; search still works.
2. **Mute every sport I haven't selected** — Settings › Mute. One checkbox that mutes every sport that is not a favorite (including sports added later); unticking restores the earlier mutes; disabled with "Pick favorite sports first" while no favorites are picked (the v1.1.0 all-sports default).
3. **Account favorites that survive cleared cache/cookies** — *proposal only*: `PROPOSAL-account-sync.md` with three options, a recommendation and five 390px mockups (`docs/mocks/account-*.png`). Nothing was built.
4. **Who and what on every Gamecast** — every sport's play list, "last play" banner and graphic caption say what happened and who was involved with their role, from ESPN play data (NCAA.com where ESPN lacks it).
5. **Bug found and fixed by QA** — Settings switches/checkboxes silently did nothing (the page's click handler returned `false`, which cancels the click). Pre-existing since the first commit.

## Caveats (read before approving)
- **Item 3 is a proposal only.** Render's free disk is ephemeral, so favorites cannot be stored in the app's files; the proposal recommends an external database (Neon Free). Prices and free-tier limits were checked on the vendors' official pages on Oct 28, 2026 and can change. Effort estimates are mine; domain cost and Google OAuth terms were not verified.
- **Release name "Pick Six" is my choice**, not Justin's.
- **Live smoke depends on the season.** College basketball (men's/women's) had no game today; the NCAA.com fallback is covered by fixtures and an outage test but was not live-verified. Basketball roles (who assisted/rebounded) are partly heuristic from ESPN text.
- **Tennis** has no point-by-point in ESPN's feed, so the story is set-by-set. **Golf** has no play timestamps and finished events have no hole data, so the "latest holes" feed is fixture-tested only (next event starts Oct 29). **UFC** uses the event-card story (ESPN `/summary` returns 404).
- **Football** play text is abbreviated; names that cannot be matched to a roster entry fall back to a tidied token, never an invented player.
- The football live "Last play" banner is live-only; finished games show a "Final play" banner.
- Mute-unselected deliberately never uses words like "playoff" or "bowl" as unselected-sport mute words, and words shared with a selected sport are never muted (otherwise it would hide the sports you picked).
- The Settings-switch bug fix could not be verified on the live site (it returned 503 when checked); it was reproduced on the v1.2.0 code. It likely means Sources, Appearance and other Settings switches did not toggle on v1.2.0.
- Search in the picker is substring-based ("bos" also matches "Lobos").
- Tested in Chromium mobile emulation at 390px, not real iOS Safari.
- `live-results.json` (a v18 verification artefact) shows as modified in the working tree and is intentionally not part of this release.

## Defects found during QA and what was done (honest log)

**Product defects (real bugs, all fixed before the final run):**
1. *Settings switches and checkboxes did not toggle.* The first browser QA run failed 8 mute cases because tapping a checkbox on a Settings page did nothing. Cause: `bindPrefs` set `root.onclick = (e) => prefClick(e, root)` and `prefClick` returns `false` when nothing matches; an `onclick` property handler that returns `false` cancels the click, so the browser never toggled the checkbox. Pre-existing since the first commit (reproduced on the v1.2.0 code); not verified on the live site (503 when checked). **Fixed** in `public/app.js` and covered by R-24 (Sources switch toggles).
2. *Soccer shot captions threw* (undefined variable in `shotCap`), found by the per-sport fixtures. **Fixed.**
3. *Duplicate function name* `teamRow` (the new picker row clashed with the existing one). **Renamed** `pickRow`.
4. *Play wording:* football penalty text, hockey roles and NBA blocked shots, college-baseball name cleaning, golf leaders, a 14-day look-back for daily sports, and https-only headshots (an `http://` headshot URL would be blocked as mixed content). **Fixed**, each with a fixture or a case (GC-03).
5. *UI polish found from screenshots:* the long mute explanation was truncated with an ellipsis at 390px (now wraps); mock wording/truncation.
6. *Unverified claim removed* from the proposal (a Turso point-in-time-recovery statement that I could not confirm in official docs).

**Test-script defects (the product was right, my test was wrong):** first full run 96/108. Besides the bug above: the news mock lacked the `status` array the client reads; AS-03 regexes were case-sensitive (CSS upper-cases headings); GC-03 waited for a *visible* element instead of an attached one; S-03 could not intercept the service-worker script fetch with `page.route` (replaced by a small proxy); R-18's length threshold; P-01's text check; MU-06's news check ran with "This sport only" on, which legitimately hid non-football stories (now off, to isolate the mute behaviour).

**Not tested / limits:** real iOS Safari; Render free-plan cold start; the live site (nothing deployed); college basketball and the NCAA.com play-by-play fallback against live data (off-season / no game today); account sync (proposal only). Final run: **109/109 pass** on the committed code.
