## What's in this release
**(A) Big-play animations on the Gamecast.** When a big play appears in a game that is in progress — a touchdown or long pass/run, a home run or grand slam, a three or a buzzer-beater, a goal, a red card, a golf eagle — the play's card in the Gamecast pops out with an animated callout (edge flash in the team colour, headline, count-up yardage/feet; the biggest plays add a shake, spotlight and confetti). Plays are flagged only from real ESPN fields (or the text ESPN printed); nothing is guessed.

| Sport | Big (flash + callout) | Huge (adds shake, spotlight, confetti) |
|---|---|---|
| Football (NFL, college) | any touchdown, 2-pt conversion, pass/run 20–39 yd, interception, lost fumble, field goal 50–59 | TD of 40+ yd or any return TD (pick-six), pass/run 40+ yd, interception returned 40+, sack-fumble lost, safety, field goal 60+ |
| Baseball (MLB, college) | home run, triple, a hit scoring 3+ runs, a hit that takes the lead or ties from the 7th on | grand slam, walk-off, HR that takes the lead or ties from the 7th on |
| Basketball | made 3, dunk, and-one, buzzer-beater, go-ahead/tying basket in the last 2:00 | 4-point play, buzzer-beater that wins/ties, go-ahead/tying basket in the last 0:30 |
| Hockey | goal (power-play / empty-net labelled) | OT goal, short-handed goal, goal that ties in the last 2:00 of the 3rd |
| Soccer | red card, penalty saved/missed | goal, penalty goal, own goal |
| Golf | eagle | albatross or hole-in-one |
| Tennis | — (ESPN has no point-by-point data, so nothing is flagged) | — |
| Other sports | any play ESPN itself flags as scoring | — |

Animation rules: it plays once per new big play while you are watching an in-progress game; opening a game never replays old plays; several new plays in one refresh collapse into one animation (the biggest, latest); finished games never auto-animate (the star badge stays in the play list); `prefers-reduced-motion` gives a static highlighted card; the overlay never blocks taps. Only transform/opacity animate.

**(B) Recovery-code account sync (no email, no password).** Settings › Account › "Create my recovery code" shows a code like `7K2M-9QXD-4TRA` once; the app then backs up favorites, mutes and settings 3 s after each change. On a new device: Settings › "I already have a code" → type it (any case, dashes optional) → "Use the backup" or "Merge". Server: Neon Postgres over HTTPS (`@neondatabase/serverless`); only a keyed hash of the code is stored (never the code), rate-limited, size-capped, fail-soft (the app works exactly as before when the database is unavailable or not configured — the card then says "Sync not available"). Two devices that edit at once are merged: lists are unioned; a single setting a device did not change is taken from the other device, one it did change wins. QA ran the sync server against a **throwaway schema** in the real Neon database, which was dropped at the end (`remaining=0`); production tables were never touched.

**Extra fix — "Tab/data mismatch on Rankings pages" (reported by Justin with a screenshot).** With CFB as the saved sport, Rankings › NFL › Bracket showed NFL data but highlighted the CFB chip. The chip strip (and its `aria-pressed`, the accent colour, backdrop and page title) now follow the sport in the URL on `#/rankings/(lists|list|playoffs)/<sport>`; elsewhere they follow the saved sport. A sport shown that has no chip highlights nothing rather than a wrong sport. Regression: unit test `tests/tabsport.test.mjs` (11 assertions) and browser cases TM-01…07; screenshot `screenshots/v21/qa-tm-nfl-bracket-390.png`.

## Caveats (read before approving)
- **The live big-play smoke was not run, and there was no live game to watch.** The animation is verified against real recorded ESPN fixtures, synthetic edge cases (labelled as such) and injected plays in a real browser at 390px. Whether the thresholds feel right during a real game is for Justin to judge on the first live game after release.
- **Thresholds are heuristics** (listed above). Basketball threes are frequent, so a game can animate often; a "big plays on/off" toggle is a sensible follow-up.
- Tennis has no data. Golf eagles need the hole's par from ESPN. The college-sports NCAA.com fallback is text-only, so only plays whose text states the event plainly are flagged. The play list shows only recent plays. Red-card team side depends on ESPN's wording.
- **Sync limits:** a lost code cannot be recovered (by design: no email or password); there is no QR code and no "I have a code" on the first onboarding screen yet (it is in Settings); `blockOutlets` and `sources` are synced beyond what the proposal listed; the first request after the Neon database sleeps can be slow (the app waits quietly and falls back to local only); rate limits are per server instance and in memory; the server trusts one proxy hop (`trust proxy` 1), so behind Cloudflare the client IP is coarse.
- **To turn sync on in production** the Render service needs `SYNC_PEPPER` plus a database URL (`NEON_DATABASE_URL` or `DATABASE_URL`, optional `SYNC_SCHEMA`); without them the card shows "Sync not available" and nothing else changes. No secret is in the repository or in this report.
- A rare UI race exists from before this release: if an in-flight Home load finishes after you open another page very quickly, the slower page can briefly be replaced. It showed up only under heavy QA load (and is why the QA waits for the network to settle after skipping onboarding); it was not changed in this release.
- Not tested: real iOS Safari, Render free-plan cold start, the live site (nothing deployed). Release name "Hail Mary" is my choice.

## Defects found during QA and what was done (honest log)

**Product defects (real bugs, fixed before the final run):**
1. *Tab/data mismatch on Rankings pages* (reported by Justin): the NFL bracket highlighted the CFB chip. Fixed with `shownSport()` (see "What's in this release"); regression unit test and TM-01…07.
2. *Restore screen crashed* (found by the first full QA, SY-07/08/09/13/15): the restore box was marked `data-part="restore"`, and `refreshParts()` empties every `data-part` element, so the form's buttons never existed and the binding dereferenced null. Fixed: the box is a plain element bound once.
3. *Account card on a server with no database/pepper* showed a Create button that could not work. It now says "Sync not available" (and no Create / "I already have a code" links); the card is shown whenever the server answers.
4. *Stale values overwrote another device's change* (found by SY-09): on a two-device conflict the device that synced second kept **all** of its own single values, so a device that only toggled "Straight news only" also reverted a theme change made on the other device. The client now remembers what it last synced and, on a conflict, keeps a single value only if this device changed it; lists are still unioned. Unit tests updated and extended.

**Test-script defects (the product was right, my test was wrong):** first full run 183/195 with 12 failures. SY-02 and SY-03 had wrong expectations (health endpoint, case-sensitive text); TM cases waited for a visible element that is only attached; U-17 (the secret scan) tripped on key-like test literals (pepper strings), which were rebuilt so test data does not look like a secret; SY-07/08 did not re-open the restore page after skipping onboarding (skipping onboarding always lands on Home, by design) and now wait for the network to settle; SY-15 now accepts the one browser network error that the deliberate offline step in SY-10 produces. GC-L-nhl failed on a transient ESPN 502: the harness retries 5xx twice and, if ESPN is still down, records a documented **SKIP** with the reason (it never counts as a pass).

SY-09 and SY-10 had the direction of the "Straight news only" toggle backwards (the app default is on, so the test's "other device" value was wrong); they now assert the correct values (theme=dark from device B, straightOnly=false from device A) and pass.

**Final full run: 194 pass / 1 fail / 0 skip of 195; the one failure is a flaky timeout, not a product defect.** BP-T-epl (Big plays UI, EPL tab) failed once with `waitForSelector('.bpo'): Timeout 20000ms exceeded` while the Premier League game feed was slow. Run alone (`QA_ONLY='^(BP-T)'`) all 5 BP-T cases passed (5/5), and the case passed again in the later subset runs. I raised that wait to 45 s (a test-only change). After the change I did **not** rerun the whole suite (about 25 minutes); instead I reran only the affected groups: BP-T, TM and SY (27/27 pass) and BP-FR/F/B/C/RM (11/11 pass), each with the test schema removed afterwards (`remaining=0`). The table below keeps the full run's recorded result, so BP-T-epl shows as FAIL.

**Process notes:** nothing was pushed or deployed. The QA's sync cases use only a throwaway database schema (`sync_test_<random>`) that the harness drops at the end and verifies (`remaining=0`); the database URL was never printed or written to a file.

**Not tested / limits:** real iOS Safari; Render free-plan cold start; the live site (nothing deployed); live big-play behaviour in a real in-progress game (no live game; fixtures and injected plays only). Full run: **194 pass / 1 fail / 0 skip of 195** on the committed code.
